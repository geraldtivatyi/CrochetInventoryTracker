# AI Development Notes

This project was created and refined with AI assistance as a productivity and debugging accelerator, not as a substitute for engineering ownership.

## How AI was used
AI was used to help with several practical development tasks, including:
- generating initial project structure and boilerplate
- speeding up debugging of TypeScript and integration issues
- reviewing build and runtime configuration
- suggesting patterns for frontend/backend integration
- improving iteration speed on UI and validation updates

## Why this matters
The goal was not to automate the entire product, but to increase efficiency in the same way a developer might use a strong assistant for research, scaffolding, and troubleshooting. This project benefited from AI especially during infrastructure setup and debugging cycles, where the assistant helped narrow down issues quickly and reduce time spent on repetitive setup work.

## Manual implementation and ownership
I manually implemented and validated the core product features, including:
- inventory CRUD workflows
- project and pricing logic
- UI refinement and user experience improvements
- database model decisions and persistence updates
- business rules for costs, currency formatting, and validation

Any AI-generated suggestions were treated as starting points and were reviewed, adapted, and corrected based on the actual product requirements and runtime behavior.

## Interview framing
This project demonstrates a balanced engineering approach:
- AI was used to accelerate setup and debugging efficiency
- I retained direct responsibility for feature development and correctness
- I applied judgment to architecture decisions, implementation details, and user-facing behavior

In other words, AI was an enabler for speed and debugging productivity, while the final product reflects my own technical decisions and hands-on engineering work.
